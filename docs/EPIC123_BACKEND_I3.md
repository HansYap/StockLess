## 架构和已确认口径

沿用 `backend/` 的浏览器兼容 TypeScript 业务引擎，通过 Web Worker 执行导入、校验和预测。当前项目没有 HTTP 后端、服务器数据库或账户系统；本次没有新增这些服务。前端实际调用业务引擎的输出。

- 一个数据集使用 MYR。
- Unit Cost 是与销量、库存相同单位的采购成本；不做包装单位自动换算。
- 需求预测使用正销量，退货单独保留；历史净销量继续保留。
- 未输入、不可用、缺少记录和数值零分别表达。

## 代码入口

- `backend/src/product-values.ts`：成本/重量验证、校验证据键、共用金额计算。
- `backend/src/assessments.ts`：每商品可用分析状态。
- `backend/src/readiness.ts`、`identity.ts`：行就绪、身份冲突和自动重复处理。
- `backend/src/forecast.ts`：需求证据、历史改善及冲突保护。
- `backend/src/correction-report.ts`：完整来源报告。
- `frontend/src/screens/excel-workbook.ts`：纯 Excel 解析；`excel-import.ts` 与 `workers/excel-import.worker.ts`：可取消 Worker 适配。
- `frontend/src/App.tsx`：映射撤销及旧就绪/预测结果失效。

## 验证

以下检查在修改后的工作区实际运行：

- 后端 Node tests：53/53。
- 前端 Vitest：82/82，16 个测试文件。
- 本地存储/路由 Node tests：3/3。
- 后端及前端 TypeScript 类型检查通过。
- Vite 生产构建通过（Excel Worker 使用 ES modules，解析和 Worker 适配分离）。
- 浏览器操作：样例导入→撤销成本映射→批量确认→就绪→采购→影响；0 显示 MYR 0.00，空订单显示未输入，同成本 10 × 2.5 在两页均为 MYR 25.00。
- 双工作表合成 XLSX：选择 Chosen Sales，仅导入 8 行，000101 保留前导零；手动完成不确定列匹配后全部行就绪，40 × 2.5 为 MYR 100.00。
- 合成容量检查：100,000 行、100 商品、3,878,929 bytes 的 CSV。本机 Node 导入约 173 ms、就绪约 1,431 ms、每商品分析约 888 ms；100,001 行正确拒绝。该结果只代表此合成数据和本机 Node，不代表所有文件、浏览器或设备性能认证。
